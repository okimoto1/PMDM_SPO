# Improving Pocket-Conditioned 3D Molecular Generation via Step-by-step Preference Optimization with Human Feedback

This repository provides the official implementation and pretrained models for the paper (link to be added upon publication).

---

## Overview

This repository provides the official implementation of a method that improves pocket-conditioned 3D molecular generation via **Step-by-step Preference Optimization (SPO)** with human feedback. Building on the existing diffusion model [PMDM](https://github.com/Layne-Huang/PMDM) (Huang et al., *Nat. Commun.* 2024) as the base model, we introduce the following:

1. **Step-aware Preference Model (SPM)** — A preference model trained on human pairwise annotations that captures medicinal-chemistry intuition beyond standard metrics such as QED and SA.
2. **Fine-tuning with SPO** — Fine-tuning PMDM with a multi-objective reward composed of the SPM score, QED, SA, and a clash penalty over the reverse diffusion process.
3. **Multi-objective improvement** — Compared with the PMDM baseline, our method improves several key drug-discovery metrics.

## Requirements

All experiments were conducted in a Docker environment. We recommend using the provided Docker setup for reproducibility. See [Usage](#usage) for how to start the container.

### Environment

The experiments were performed in the following environment. CUDA and Python are included in the Docker image, so you do not need to install them separately.

- GPU: NVIDIA A100 / H200
- CUDA: 11.8 (included in the Docker image)
- Python: 3.11 (included in the Docker image)
- OS (base image): Ubuntu 20.04

### External tools

**OpenBabel** (used for bond construction) is required for PMDM to run. It is installed automatically during the Docker image build.

**QuickVina2** is optionally used for Vina docking, which is disabled by default. If you want to run Vina docking, please set it up yourself (see the PMDM repository).

These tools are not redistributed in this repository and retain their own licenses.

## Data

### CrossDocked2020

We use the CrossDocked2020 dataset, following the same split as the original PMDM paper. The raw data, `split_by_name.pt`, and `index.pkl` are available from the PMDM Zenodo record ([10.5281/zenodo.10630921](https://doi.org/10.5281/zenodo.10630921)). The preprocessed data (`processed.lmdb`, `name2id.pt`) is generated following the PMDM procedure. (For reference, the preprocessed data used in this work is also provided via Zenodo (DOI: to be added upon publication).)

### SPM Training Data and Annotation Database

Training the SPM uses human preference annotations over compound pairs. These annotations are collected in `spo/db.sqlite` (SQLite format), which contains the compound pairs and their preference labels. `db.sqlite` is included in this repository.

The 3D structure data of the annotated compounds (`ligand_data`) is distributed via Zenodo (DOI: to be added upon publication) because the data size is large. Download and extract it under `spo/`. These compounds come from two sources: compounds generated by PMDM, and compounds taken from the publicly available Namiki HTS Library (2023 version, [Namiki Shoji Co., Ltd.](https://www.namiki-s.co.jp)), used with permission from the provider.

This data is used to train the SPM in the training step (Step 1 in [Usage](#usage)).

## Usage

All commands from Step 1 onward are executed inside the Docker container.

### 0. Start the Docker environment

```bash
# Build and start the container
docker compose up --build -d

# Enter the container
docker compose exec pmdm_spo /bin/bash

# To stop and remove the container when you no longer need it
docker compose down
```

By default, the repository is mounted at `/workspace` inside the container. If you keep your dataset outside the repository, edit the data mount path in `docker-compose.yml`.

### 1. Train the SPM

Before running this, place `spo/ligand_data` in position (see [Data](#spm-training-data-and-annotation-database)).

```bash
python spo/ligand_spm/train_debias.py \
    --data_dir spo/ligand_data \
    --db_path spo/db.sqlite \
    --output_dir ./checkpoints_debias
```

### 2. Hyperparameter Search (Grid Search)

```bash
./grid_search_spo.sh
```

This script uses `trained_models/500.pt` (the PMDM base model) and `trained_models/spm_v4.pt` (the SPM). Settings such as the model paths and the search configuration are defined within the script.

Results are saved to `grid_search_spo_<timestamp>/grid_search_results.csv`.

The search space is:

- `w_spm`: [0, 0.25, 0.5, 0.75, 1.0]
- `w_qed`: [0.25, 0.5, 0.75, 1.0]
- `w_sa`: [0.25, 0.5, 0.75, 1.0]
- `w_clash`: [0.25, 0.5, 0.75, 1.0]

### 3. SPO Fine-tuning

```bash
python train_spo_pmdm.py \
    --pmdm_ckpt trained_models/500.pt \
    --spm_ckpt trained_models/spm_v4.pt \
    --config configs/crossdock_epoch.yml \
    --output_dir logs/spo_pmdm \
    --score_weight_spm 0.25 \
    --score_weight_qed 0.25 \
    --score_weight_sa 0.5 \
    --score_weight_clash 1.0
```

Training was performed for 1509 batches (about 1 epoch, roughly 3 days) on 8x H200 GPUs.

### 4. Convert the Checkpoint

> If you use the pretrained model included in the repository (`trained_models/spo_b1509.pt`), this step is not necessary. Run it only if you performed SPO training (Step 3) yourself.

Checkpoints obtained from SPO training must be converted to the PMDM-compatible format before sampling.

```bash
python convert_spo_checkpoint.py spo_checkpoint.pt \
    --original trained_models/500.pt \
    --output trained_models/spo_converted.pt
```

After conversion, specify the converted file (e.g., `trained_models/spo_converted.pt`) as `--ckpt` in Step 5.

### 5. Sampling

```bash
python sample_batch.py \
    --dataset crossdock \
    --ckpt trained_models/spo_b1509.pt \
    --num_samples 100 \
    --sampling_type generalized
```

### 6. Evaluation

```bash
./eval_all.sh <pkl_file> [output_dir]
```

This computes a set of molecular quality metrics and outputs a summary of the results. The metrics include QED, SA, logP, Lipinski, molecular weight, diversity, collision frequency, Brenk violation rate, and ring size distribution.

To evaluate with external tools (PB-valid, AiZ), first generate SDF and PDB files from the sample file:

```bash
python scripts_for_eval/generate_sdf_pdb.py --samples_file <pkl_file> --output_dir <output_dir>
```

The generated SDF/PDB files can then be used as input to the external tools.

## Results

Comparison of molecular quality metrics on the CrossDocked2020 test set (100 compounds per target across 100 test proteins; 10,000 compounds in total). Up arrow indicates higher is better; down arrow indicates lower is better.

| Model | QED ↑ | SA ↑ | RO5 ↑ | MW | Div ↑ | PB-valid ↑ | Brenk ↓ | AiZ ↑ |
|---|---|---|---|---|---|---|---|---|
| PMDM (base) | 0.56 | 0.63 | 4.85 | 280 | 0.78 | 0.52 | 0.47 | 0.13 |
| **PMDM (SPO)** | **0.63** | **0.69** | **4.91** | **266** | **0.79** | **0.79** | **0.35** | **0.21** |

QED: quantitative estimate of drug-likeness; SA: synthetic accessibility; RO5: mean number of Lipinski's Rule of Five criteria satisfied; MW: mean molecular weight (Da); Div: internal diversity; PB-valid: fraction passing all PoseBusters checks; Brenk: fraction containing one or more undesirable structural patterns (Brenk filter); AiZ: fraction with a retrosynthetic route identified by AiZynthFinder.

These values are those reported in the paper. For some metrics, the values may differ from the output of `eval_all.sh` due to differences in processing. In addition, PB-valid and AiZ are not included in `eval_all.sh` and are evaluated separately using external tools ([PoseBusters](https://github.com/maabuu/posebusters) and [AiZynthFinder](https://github.com/MolecularAI/aizynthfinder), respectively).
